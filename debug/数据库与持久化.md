# 数据库与持久化问题族

## 集合写入的类型边界

- PostgreSQL 参数传入 `jsonb` 时必须使用 `jsonb_to_recordset`；`json_to_recordset(jsonb)` 会触发 SQLSTATE `42883`，不能靠重试恢复。
- recordset 列表为空时直接返回，非空时显式声明 UUID、数组、numeric/text 类型；事务、唯一约束和 `ON CONFLICT` 语义不得因批量化改变。
- 发布事务仍按“创建快照 → 批量写切片 → 最后切换当前指针”执行，任何中间失败都不能留下新指针。

## 隔离测试数据库

- 性能样本只写 `revenue_and_costs_codex_test` 的全新 `perf_opt_*` schema；每个 schema 只运行一次并保留证据。
- 汇率种子只从业务库读取经校验的只读覆盖，其他业务事实不得复制或写回。
- 本机 `template1` 含其他项目遗留表，恢复演练数据库必须从干净 `template0` 创建；否则 `pg_dump` 会锁定无关表并因权限失败。
- 恢复目标必须是独立且空的数据库，先验证加密清单/HMAC，再解密、恢复和检查账本、版本指针、对象引用与迁移数；不得在业务库上做恢复演练。
