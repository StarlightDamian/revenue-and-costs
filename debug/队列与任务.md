# 队列、Worker 与任务状态问题族

## DBG-E87FB7C29137：确定性查询错误被当作可重试任务

- 稳定信号：同一业务键重复出现 PostgreSQL `42P08` / SQLSTATE 42；代码和 schema 未变化，后续尝试仍失败。
- 根因：导入提交分类器没有把查询契约错误投影为终态，Worker 重抛后 pg-boss 按配置继续租约和退避。
- 修复：失败事务先回滚，再把 SQLSTATE 42 映射为脱敏 `IMPORT_QUERY_INVALID`，持久化批次失败和问题记录；Worker 识别已持久化终态并完成本次消费，不再重试。
- 验证：历史同一任务至少连续 3 次同错；分类、持久化、Worker 生命周期回归和完整测试门禁通过。
- 失效条件：连接、序列化、死锁、租约超时或容量错误仍需按各自瞬态语义处理，不能一概终态化。

## 通知、轮询与恢复约束

- pg-boss 是租约、心跳和重试的唯一事实来源；业务进度表不实现第二套抢占队列。
- outbox 和 pg-boss 使用提交后 `LISTEN/NOTIFY` 唤醒并保留 1 秒兜底；通知可丢，业务事实和幂等键不可丢。
- outbox 按 topic 批量分发，但不引入固定 10 ms 合并延迟；已有真实配对证明收益不足 5%。
- 确定性导出或导入失败必须进入可查询终态并保留安全错误码；增加重试次数、sleep 或前端轮询不能修复根因。
- 任务 ack 前必须先提交幂等业务结果；重启恢复不得重复扣款、入账、发布或生成不同产物。
- 当前最终套件的缓存复用均返回同一 `exportId`、字节数与 SHA-256；显式 PostgreSQL/隔离恢复门禁 15/15 通过，未发现重复发布、重复导出或悬挂任务。

## 排查顺序

1. 以业务键关联 outbox、pg-boss job、业务状态和结构化错误码。
2. 区分排队等待、租约执行、心跳丢失、确定性失败和瞬态数据库错误。
3. 检查是否已提交终态；不要仅凭进程存在或前端 `RUNNING` 判断任务仍有效。
4. 对重复失败比较归一化 SQLSTATE/异常，而不是时间戳、job UUID 或请求 ID。
