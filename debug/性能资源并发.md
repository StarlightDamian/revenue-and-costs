# 性能、资源与并发问题族

本文件只保留可复用的诊断结论；完整状态、成对数据和下一步以 `nas/doc/1-技术架构/上传计算下载性能优化状态.md` 为准，原始证据只在 `.work/performance-test-drive/`。

## DBG-674AF32B4E4F：有界逐文件/逐切片 SQL 循环

- 稳定信号：同一 SQL 指纹按文件或切片重复；业务行数不变，但 statement count 线性增长。
- 根因：调用方已经持有完整、有界结果集，却仍循环执行同形 `INSERT` / `UPDATE`。
- 修复：在原事务内使用 `jsonb_to_recordset` 一次写入；事实读取继续分页，文件处理继续逐任务隔离，不能把无界流改成一个大 JSON。
- 当前证据：计算切片 34 → 1 条、发布快照切片 68 → 1 条、导入文件计数与问题 36 → 2 条；八位财务结果、行数、切片和五 Sheet 语义保持一致。
- 反例：10 ms outbox 合并只有 -4.62% 目标查询和约 -1% 处理 SQL，且无墙钟收益，已撤回；不要用固定延迟掩盖写入结构问题。

## DBG-9191BB053B77：共享宿主负载污染性能比较

- 稳定信号：`PERFORMANCE_HOST_BUSY`；候选前后 SQL/正确性稳定，但 E2E 随无关 Python/桌面进程负载同步漂移。
- 根因：共享宿主的调度和文件缓存不是候选补丁的一部分，忙机墙钟无法归因。
- 门禁：每个样本前固定采集 5 秒总 CPU 和可用内存；平均 CPU >20% 时不创建 schema、不启动 API/Worker、不计入样本。不得为制造干净数据而停止不属于本任务的进程。
- 最终协议：首轮与扩展轮各按每家公司 1 次不计入统计的全新 schema 预热 + 5 次全新 schema 测量；合并后为每家公司 2 次预热、10 次测量。每个样本内部验证相同参数复用。10 个样本的 nearest-rank P95 仍只作描述性最大值，同时报告全部原值、min、median、总体标准差和 CV。
- 最终证据：30 个测量样本全部成功并保留。三家公司业务 E2E 中位数分别为 54.829、7.132、10.328 秒；业务 CV 为 13.54%、17.34%、32.91%，但 SQL 数量 CV 仅 4.17%、1.79%、3.77%，WAL CV 仅 4.57%、0.68%、1.04%，正确性签名、数据库增量和 RSS 稳定。剩余波动归因于同宿主 CPU、数据库 I/O 与缓存状态，不删除离群样本。

## DBG-BFA222C33BED：同步采样造成异步业务计时观察者效应

- 稳定信号：分阶段计时之和显著小于驱动墙钟；驱动同步扫描存储或收集 SQL/资源快照时，独立 Worker 仍在推进业务。
- 根因：旧驱动把采样开销排除在阶段计时外，却没有暂停 Worker，导致真实业务工作落在计时边界之外。
- 修复：从上传开始到首次完整下载只保留一个不间断单调时钟；阶段归因只读取驱动/Worker 事件；SQL、WAL、资源和存储快照只在业务区间前后采集，复用的存储快照显式标记 `measured=false`。
- 验证：`observer_smoke_20260806_v2` 的业务时长 45,112.67 ms，阶段和 45,100.17 ms，未归因胶水仅 12.51 ms；旧 v3 计时保留但排除，最终 v4 与扩展轮共 30 个测量样本全部使用新边界。

## 并发与资源审查清单

1. 用 statement 指纹、行数和 `EXPLAIN (ANALYZE, BUFFERS)` 证明热点；不从循环外观推断 N+1。
2. 同时核对 API/Worker CPU、峰值 RSS、临时目录、PostgreSQL SQL/WAL/临时文件和队列等待。
3. 批量写入必须有明确上界；大文件仍使用流、背压、分页和 COPY。
4. 性能补丁必须成对验证正确性；无可归因的阶段收益或目标阶段 <5% 就撤回。
5. 停止运行态时只使用本轮进程清单并验证命令行；永不停止 PostgreSQL。
6. 异步系统的业务计时不能在中途执行同步 profiler、数据库或递归存储采样；观察开销必须单列。
